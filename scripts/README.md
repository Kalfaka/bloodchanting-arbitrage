# Scripts Directory

## Overview

This directory contains three scripts that work together to optimize bloodchanting arbitrage analysis:

```
┌─────────────────────────────────────────────────────────────┐
│                    WORKFLOW DIAGRAM                          │
└─────────────────────────────────────────────────────────────┘

1. fetch_trade_data.py (SLOW - Run Monthly/Quarterly)
   ├─> Fetches ALL ~217 shop items
   ├─> Gets 90 days of trade history
   ├─> Takes 15-30 minutes
   └─> Outputs: data/trade_cache.json (~5-10 MB)
        │
        ▼
2. generate_top_items.py (Run After Full Fetch)
   ├─> Analyzes 30-day window trade data
   ├─> Calculates conversion rates (bags/shard, bags/token)
   ├─> Selects top 25 items from each shop
   ├─> Uses volatility as secondary criteria
   └─> Outputs: data/top_items.json (50+ items)
        │
        ▼
3. fetch_top_items.py (FAST - Run Hourly)
   ├─> Fetches ONLY items in top_items.json (~50 items)
   ├─> Gets recent trade history
   ├─> Takes 30-60 seconds
   └─> Outputs: data/trade_cache.json (~500 KB)
```

**Typical Usage:**
- Monthly/Quarterly: Run full fetch → regenerate top items → verify changes
- Hourly: Run optimized fetch → update analysis → refresh frontend

## fetch_trade_data.py

Python script that fetches trade data from the SpawnPK API and saves it to `data/trade_cache.json`.

### What it does:

1. Reads item names from `data/blood_shard_shop.json` and `data/blood_synthesis_shop.json`
2. Fetches trade history for each item from the SpawnPK API
3. Combines all trades into a single JSON file
4. Adds metadata (timestamp, trade count, etc.)
5. Saves to `data/trade_cache.json`

### Usage:

```bash
# Install dependencies
pip install -r requirements.txt

# Run the script
python scripts/fetch_trade_data.py
```

### Configuration:

- **Rate limit:** 0.1s delay (10 req/sec) - tested safe for direct API access
- **Max pages per item:** 5 pages (75 trades max per item)
- **Output file:** `data/trade_cache.json`

### Performance:

- **Items fetched:** ~217 unique items
- **Execution time:** ~2-3 minutes
- **Output size:** ~500KB - 1MB

### Output Format:

```json
{
  "metadata": {
    "last_updated": "2026-01-13T01:30:00.000000",
    "total_trades": 5000,
    "items_processed": 217,
    "items_with_trades": 150,
    "source": "GitHub Actions",
    "api_url": "https://..."
  },
```

## generate_top_items.py

Python script that analyzes trade data to identify the most profitable items for bloodchanting arbitrage.

### What it does:

1. Loads complete trade data from `data/trade_cache.json` (generated by `fetch_trade_data.py`)
2. Analyzes last 30 days of trades for each shop item
3. Calculates conversion rates (bags/shard or bags/token) - **lower is better**
4. Calculates volatility (coefficient of variation) as secondary metric
5. Selects top 25 items from Blood Shard shop (lowest conversion rate)
6. Selects top 25 items from Blood Synthesis Token shop (lowest conversion rate)
7. Always includes critical items: Blood diamonds, Bloodchanting stone
8. Saves optimized list to `data/top_items.json`

### Selection Criteria:

**Primary:** Conversion Rate (ascending)
- Formula: `median_price / shop_cost`
- Lower = cheaper to acquire shards/tokens = better arbitrage
- Example: 47.00 bags/shard is better than 55.00 bags/shard

**Secondary:** Volatility (ascending)
- Formula: `(std_price / mean_price) × 100`
- Lower = more stable/predictable prices
- Used as tiebreaker when conversion rates are similar

**Minimum Trades:** 3 trades in 30-day window required

### Usage:

```bash
# PREREQUISITE: Run full fetch first
python scripts/fetch_trade_data.py

# Generate top items list
python scripts/generate_top_items.py
```

### GitHub Actions Workflow:

**When to run:**

**What it does:**
1. Fetches ALL shop items (90 days of data)

### Performance:

- **Analysis time:** 5-10 seconds
- **Input:** Full trade cache (~5-10 MB)
- **Output:** Top items list (~5-10 KB)

### Important Notes:

2. **Deduplication** happens at fetch time - final list contains unique item names
3. **Critical items** (Blood diamonds, Bloodchanting stone) always included regardless of metrics
4. **This script should run AFTER** `fetch_trade_data.py` has generated full trade cache
5. **Next step after generation:** Run `fetch_top_items.py` to get fresh data for new items

## fetch_top_items.py

Optimized Python script that fetches trade data for ONLY the top-performing items (fast, frequent updates).

### What it does:

1. Loads item list from `data/top_items.json` (~50 items)
2. Always includes critical items: Blood diamonds, Bloodchanting stone
3. Fetches recent trade history for each item from SpawnPK API
4. Saves to `data/trade_cache.json` (same format as full fetch)

### Key Differences from fetch_trade_data.py:

| Feature | fetch_trade_data.py | fetch_top_items.py |
|---------|---------------------|-------------------|
| **Items** | ALL shop items (~217) | Top items only (~50) |
| **Time** | 15-30 minutes | 30-60 seconds |
| **Size** | 5-10 MB | 500 KB |
| **When** | Monthly/Quarterly | Hourly |
| **Purpose** | Generate top items | Update analysis |

### Usage:

```bash
# Install dependencies
pip install -r requirements.txt

# Run optimized fetch
python scripts/fetch_top_items.py
```

### GitHub Actions Workflow:

Automatic workflow: **Update Top Items (Optimized)**

```yaml
# Trigger manually from GitHub Actions tab
# Location: .github/workflows/update-top-items.yml
```

**When to run:**
- Hourly for fresh data (manual trigger only)
- After running "Regenerate Top Items List" workflow
- Before generating new trade analysis

### Configuration:

- **Rate limit:** 0.1s delay (10 req/sec)
- **Max pages per item:** 5 pages (75 trades max)
- **Output file:** `data/trade_cache.json`

### Performance:

- **Items fetched:** ~50 items (from top_items.json)
- **Execution time:** 30-60 seconds
- **Output size:** ~500 KB

### Important Notes:

1. **Depends on top_items.json** - If this file is missing or outdated, run `generate_top_items.py` first
2. **Critical items always included** - Even if not in top_items.json
3. **Same output format** - Compatible with all analysis scripts
4. **Frequent updates** - Safe to run hourly for real-time arbitrage opportunities

## Workflow Summary

### Initial Setup (One-Time)

```bash
# 1. Fetch all items (slow)
python scripts/fetch_trade_data.py

# 2. Generate optimal item list
python scripts/generate_top_items.py

# 3. Verify top_items.json looks correct
cat data/top_items.json
```

### Regular Updates (Hourly)

```bash
# Fetch only top items (fast)
python scripts/fetch_top_items.py

# Run analysis
python trade_economics_analysis.py

# View results in browser
open index.html
```

### Monthly Maintenance

```bash
# 1. Full fetch to reassess all items
python scripts/fetch_trade_data.py

# 2. Regenerate top items (catches new high-value items)
python scripts/generate_top_items.py

# 3. Review changes
git diff data/top_items.json

# 4. If satisfied, fetch fresh data for new items
python scripts/fetch_top_items.py

# 5. Regenerate analysis
python trade_economics_analysis.py
```

### GitHub Actions Automation

**Manual Workflows:**
1. **Regenerate Top Items List** (`.github/workflows/regenerate-top-items.yml`)
   - Runs full fetch + regeneration

2. **Update Top Items (Optimized)** (`.github/workflows/update-top-items.yml`)
   - Runs optimized fetch only
   - Updates trade_cache.json
   - Run hourly or on-demand

## Troubleshooting

### "No trade data found for Blood diamonds"

**Cause:** top_items.json missing critical items

**Fix:** Run `generate_top_items.py` to regenerate list with always-included items

### "top_items.json not found"

**Cause:** Initial setup not completed

**Fix:**
```bash
python scripts/fetch_trade_data.py
python scripts/generate_top_items.py
```

### "Conversion rates seem wrong"

**Cause:** Using stale top_items.json based on old/incorrect calculations

**Fix:** Re-run generation workflow to get correct item selection

### "Rankings don't change between time windows"

**Cause:** This is a frontend issue, not a script issue

**Fix:** Check that `js/unified.js` is sorting by window-specific ROI
